## 1. 通用约定

### 1.1 基础地址

| 场景 | Base URL |
|---|---|
| 直连后端 | `http://127.0.0.1:8000` |
| 前端经 Vite 代理 | `http://localhost:5173`（`/api` 前缀自动转发到后端 8000） |

所有业务接口统一以 `/api` 开头，请求与响应均为 `application/json; charset=utf-8`（流式问答除外，见 §4）。

### 1.2 鉴权

标注「需要登录」的接口须携带请求头：

```
Authorization: Bearer <access_token>
```

令牌由 `/api/auth/register` 或 `/api/auth/login` 返回，为 JWT（HS256），默认有效期 24 小时（`JWT_EXPIRE_HOURS`）。令牌无状态：重启后端不会使其失效，过期前也无法主动吊销。

缺少请求头时 `HTTPBearer(auto_error=False)` 不会直接拦截，统一由业务依赖判定，返回 `401`：

| detail | 触发条件 |
|---|---|
| `未登录` | 没有 `Authorization` 头，或不是 `Bearer` 方案 |
| `登录已过期，请重新登录` | 令牌 `exp` 已过期 |
| `无效的登录凭证` | 签名校验失败、载荷格式非法 |
| `用户不存在` | 令牌有效但对应用户名已不在库中 |

`/api/admin/*` 下的后台接口在上述基础上再要求管理员身份（`is_admin` 为真），否则返回 `403 需要管理员权限`。注意令牌载荷里的用户名是登录时的快照：管理员在后台给自己改名后，旧令牌的 `username` 反查不到用户，需重新登录。

### 1.3 错误响应形态

| 形态 | 状态码 | 响应体 |
|---|---|---|
| 业务错误（`HTTPException`） | 401 / 403 / 404 / 409 / 422 | `{"detail": "中文提示"}` |
| 请求体校验失败（Pydantic） | 422 | `{"detail": [{"type": "...", "loc": ["body","message"], "msg": "..."}]}` |
| 未捕获异常（如大模型调用失败） | 500 | 纯文本 `Internal Server Error`，中文错误详情只写入服务端日志 |

### 1.4 会话归属规则

`conversation_id` 相关的访问统一遵循：

1. 会话不存在 → 放行（视为新会话，落库时创建并归属当前用户）；
2. 会话存在但 `user_id` 为空 → 自动认领给当前用户；
3. 会话属于他人 → `403 无权访问该会话`，管理员（`is_admin`）除外。

「放行」只适用于问答接口（需要为新会话建库）；`PATCH`（改名）与 `DELETE`（删除）要求目标会话已存在，否则返回 `404 会话不存在`。已软删除（`deleted_at` 非空）的会话对所有接口都视为不存在。命中无主会话时两者都会先认领给当前用户再执行。

### 1.5 公共数据结构

**ChatMessage**（历史与回放消息）

| 字段 | 类型 | 说明 |
|---|---|---|
| `role` | string | `user` \| `assistant` \| `system` |
| `content` | string | 消息正文 |

**TokenResponse**

| 字段 | 类型 | 说明 |
|---|---|---|
| `access_token` | string | JWT |
| `token_type` | string | 固定 `bearer` |
| `username` | string | 用户名 |
| `is_admin` | boolean | 是否管理员 |

**ConversationSummary**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string(36) | 会话 UUID |
| `title` | string | 会话名称，为空时回落为 `新会话` |
| `updated_at` | date-time | 最近一轮问答时间（无时区的北京时间墙上时间） |

**AdminUser**（后台用户管理返回，不含密码哈希）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | integer | 用户 id |
| `username` | string | 用户名 |
| `is_admin` | boolean | 是否管理员 |
| `created_at` | date-time | 注册时间 |

## 2. 数据模型

一个会话包含多轮问答，**一轮问答存为一行**（问题与回答成对）。

### 2.1 `users`

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | integer | 主键、自增 |
| `username` | varchar(64) | 非空、唯一、索引 |
| `password_hash` | varchar(128) | 非空（bcrypt） |
| `is_admin` | boolean | 默认 `false` |
| `created_at` | timestamp(0) | 默认当前时间 |

### 2.2 `conversations`

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | varchar(36) | 主键（UUID4 字符串） |
| `user_id` | integer | 外键 → `users.id`，`ON DELETE SET NULL`，可空、索引 |
| `title` | varchar(200) | 可空；会话名称，首个问题时写入，之后可改名 |
| `deleted_at` | timestamp(0) | 可空；软删除标记，为空表示未删除，非空为删除时间 |
| `created_at` | timestamp(0) | 默认当前时间 |

### 2.3 `messages`

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | integer | 主键、自增 |
| `conversation_id` | varchar(36) | 外键 → `conversations.id`，`ON DELETE CASCADE`，索引 |
| `question` | text | 非空 |
| `answer` | text | 可空 |
| `model` | varchar(64) | 可空，本轮使用的模型名 |
| `created_at` | timestamp(0) | 默认当前时间 |

## 4. 接口明细

### 4.1 健康检查

`GET /api/health` — 免鉴权，执行一次 `SELECT 1` 验证数据库连通性。

```json
{ "status": "ok", "database": "ok" }
```

数据库不可用时 HTTP 仍为 200，`database` 变为错误串，便于区分「进程活着」与「库能连」：

```json
{ "status": "ok", "database": "error: connection to server at ... failed" }
```

---

### 4.2 注册

`POST /api/auth/register` — 免鉴权，成功即返回令牌（自动登录）。

请求体：

| 字段 | 类型 | 约束 |
|---|---|---|
| `username` | string | 2–32 位，允许字母、数字、下划线、连字符、中文（`^[\w\u4e00-\u9fa5-]+$`） |
| `password` | string | 4–64 位 |

```sh
curl -X POST http://127.0.0.1:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"jiang","password":"1234"}'
```

响应 `200`：`TokenResponse`。

| 状态码 | detail |
|---|---|
| 409 | `用户名已存在` |
| 422 | 用户名/密码长度或字符集不合规 |

---

### 4.3 登录

`POST /api/auth/login` — 免鉴权。

请求体：`username`（1–64）、`password`（1–64）。

```sh
curl -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}'
```

响应 `200`：`TokenResponse`。

| 状态码 | detail |
|---|---|
| 401 | `用户名或密码错误`（用户不存在与密码错误共用，避免枚举） |
| 422 | 长度不合规 |

---

### 4.4 当前用户

`GET /api/auth/me` — 需要登录。

```json
{ "username": "jiang", "is_admin": false }
```

前端可用它做令牌有效性校验（401 时跳转登录页）。

---

### 4.5 非流式问答

`POST /api/chat` — 需要登录。

请求体：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `message` | string | 1–8000 | 本次提问 |
| `history` | ChatMessage[] | 最多 40 条，默认 `[]` | 前端持有的上下文 |
| `conversation_id` | string \| null | 可选 | 不传则后端新建会话 |

```sh
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"用一句话解释 SSE","history":[],"conversation_id":null}'
```

响应 `200`：

```json
{
  "answer": "SSE 是……",
  "model": "deepseek-chat",
  "conversation_id": "0f1c...-..."
}
```

行为说明：

- 发给大模型的消息序列为 `system 指令 + history + 当前问题`；
- `history` 为空但 `conversation_id` 指向已存在会话时，自动从库中补最近 40 条；
- 成功返回前完成落库：写入 `messages` 一行，并在会话首次出现时以其 `message` 作为 `title`；
- 未配置 `LLM_API_KEY` 时 `model` 为 `mock`，`answer` 为占位文本。

| 状态码 | detail / 说明 |
|---|---|
| 401 | 未登录类错误 |
| 403 | `无权访问该会话` |
| 422 | `message` 为空或超长、`history` 超过 40 条、`role` 非法 |
| 500 | 大模型调用失败（不落库） |

---

### 4.6 流式问答（SSE）

`POST /api/chat/stream` — 需要登录，请求体同 §4.5。

```sh
curl -N -X POST http://127.0.0.1:8000/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"讲个笑话","history":[],"conversation_id":null}'
```

响应头：

```
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
X-Accel-Buffering: no
```

事件流协议（每条事件形如 `data: <内容>\n\n`）：

| 顺序 | 事件 | 说明 |
|---|---|---|
| 1 | `data: {"delta":"","model":"deepseek-chat","conversation_id":"..."}` | 首事件固定 `delta` 为空串，携带模型名与会话 id，前端据此延续会话 |
| 2..n | `data: {"delta":"文本增量"}` | 逐块推送回答 |
| n+1 | `data: [DONE]` | 正常结束，**此后才落库**（写入本轮问答并按需写入会话名） |
| 异常 | `data: {"error":"调用大模型失败：..."}` | 流已开始无法修改状态码，故以事件下发；出现该事件则没有 `[DONE]`，本轮不落库 |

前端解析要点：按 `\n\n` 切分事件、去掉 `data: ` 前缀，`[DONE]` 表示结束。读取到 `[DONE]` 后建议 `reader.cancel()`，否则 Chrome 会在控制台记一条 `net::ERR_ABORTED`（数据本身已完整接收）。

---

### 4.7 会话列表

`GET /api/conversations` — 需要登录，返回当前用户未软删除的全部会话，按 `updated_at` 倒序。

```json
[
  {
    "id": "7f882148-26f7-4c72-81e0-246314bf0189",
    "title": "用一句话解释 SSE",
    "updated_at": "2026-10-21T17:09:12"
  }
]
```

- `title` 取 `conversations.title`，为空回落 `新会话`；
- 会话没有任何消息时 `updated_at` 取会话创建时间。

---

### 4.8 修改会话名称

`PATCH /api/conversations/{conversation_id}` — 需要登录，仅限本人会话（管理员可改任意会话）。

请求体：

| 字段 | 类型 | 约束 |
|---|---|---|
| `title` | string | 1–200 位（提交前会去首尾空白并按 200 字符截断） |

```sh
curl -X PATCH http://127.0.0.1:8000/api/conversations/7f882148-26f7-4c72-81e0-246314bf0189 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"SSE 学习笔记"}'
```

响应 `200`：返回后端最终保存的名称，前端可就地更新列表项。

```json
{ "id": "7f882148-26f7-4c72-81e0-246314bf0189", "title": "SSE 学习笔记" }
```

| 状态码 | detail |
|---|---|
| 401 | 未登录类错误 |
| 403 | `无权访问该会话` |
| 404 | `会话不存在` |
| 422 | `会话名称不能为空`（全为空白字符）；或长度非法（Pydantic 数组型 detail） |

改名只影响 `title`，不改变会话排序键 `updated_at`，因此列表顺序不变。改名后继续提问**不会**覆盖新名称。

---

### 4.9 删除会话

`DELETE /api/conversations/{conversation_id}` — 需要登录，仅限本人会话（管理员可删任意会话）。

软删除：只把 `conversations.deleted_at` 置为删除时间，会话行和会话内的消息全部保留在库内，把该列改回 `NULL` 即可恢复。删除后该会话对列表、改名、历史回放和再次删除都视为不存在。

```sh
curl -X DELETE http://127.0.0.1:8000/api/conversations/7f882148-26f7-4c72-81e0-246314bf0189 \
  -H "Authorization: Bearer $TOKEN"
```

响应 `200`：

```json
{ "id": "7f882148-26f7-4c72-81e0-246314bf0189", "deleted": true }
```

| 状态码 | detail |
|---|---|
| 401 | 未登录类错误 |
| 403 | `无权访问该会话`（会话保持不动） |
| 404 | `会话不存在`（含重复删除同一 id） |

- 命中的是无主会话时会先认领给当前用户再打删除标记，与改名接口的归属判定一致；
- 删除后若前端仍用同一个 `conversation_id` 提问，会撤销删除标记复活该会话（旧消息仍在，随后可以通过历史回放读到），但这一轮不带删除前的旧历史——补历史时已删会话读不到消息；
- 删除不会物理清理数据，`messages` 上的 `ON DELETE CASCADE` 只在直接删库中的会话行时才会触发。

---

### 4.10 会话历史消息

`GET /api/conversations/{conversation_id}/messages` — 需要登录。

按问答顺序展开为 `role/content` 序列（每行拆成 `user` + `assistant` 两条）：

```json
[
  { "role": "user", "content": "用一句话解释 SSE" },
  { "role": "assistant", "content": "SSE 是……" }
]
```

| 状态码 | detail |
|---|---|
| 401 | 未登录类错误 |
| 403 | `无权访问该会话` |
| 404 | `会话不存在或暂无消息`（已软删除的会话同样按不存在处理） |

注意：回答为 `null` 的行只产出 `user` 一条消息（异常中断的轮次不会补 `assistant`）。

### 4.11 用户列表（后台）

`GET /api/admin/users` — 需要管理员。返回系统全部用户（含管理员），按 `id` 正序。

```sh
curl -s http://127.0.0.1:8000/api/admin/users -H "Authorization: Bearer $ADMIN_TOKEN"
```

响应 `200`：`AdminUser[]`。

```json
[
  { "id": 1, "username": "admin", "is_admin": true, "created_at": "2026-10-21T16:01:30" },
  { "id": 3, "username": "jiang", "is_admin": false, "created_at": "2026-10-21T16:04:47" }
]
```

分页与筛选尚未提供，用户量变大时需再加。

### 4.12 新建用户（后台）

`POST /api/admin/users` — 需要管理员。约束与注册接口一致：`username` 2–32 位且只允许字母、数字、下划线、连字符、中文；`password` 4–64 位；额外支持 `is_admin`（默认 `false`）。

```sh
curl -s -X POST http://127.0.0.1:8000/api/admin/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"username":"zhangsan","password":"1234","is_admin":false}'
```

响应 `201`：`AdminUser`。

| 状态码 | detail |
|---|---|
| 403 | `需要管理员权限` |
| 409 | `用户名已存在` |
| 422 | 用户名/密码长度或字符集不合规 |

---

### 4.13 修改用户（后台）

`PATCH /api/admin/users/{user_id}` — 需要管理员。字段全部可选，**不传即保持原值**：`username`（改名）、`password`（重置密码，明文提交、后端 bcrypt）、`is_admin`（提升或取消管理员）。

```sh
curl -s -X PATCH http://127.0.0.1:8000/api/admin/users/3 \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"password":"newpass","is_admin":true}'
```

响应 `200`：`AdminUser`（修改后的最新值）。

| 状态码 | detail |
|---|---|
| 403 | `需要管理员权限` |
| 404 | `用户不存在` |
| 409 | `用户名已存在`（与他人冲突，改名排除自身）；`系统至少需要保留一个管理员`（取消最后一个管理员） |
| 422 | `没有需要修改的字段`；或字段长度/字符集不合规 |

给自己改名会让当前令牌失效（`get_current_user` 按用户名反查），需重新登录；重置他人密码不影响其已签发的令牌，令牌过期前对方仍能继续使用。

---

### 4.14 删除用户（后台）

`DELETE /api/admin/users/{user_id}` — 需要管理员。用户行为物理删除（`users` 表没有软删除列）；其名下未删除的会话在**同一事务内**先打 `deleted_at` 标记再删用户，避免 `ON DELETE SET NULL` 留下无主会话被后续问答认领给其他用户。会话行与消息行都保留在库内。

```sh
curl -s -X DELETE http://127.0.0.1:8000/api/admin/users/3 \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

响应 `200`：

```json
{ "id": 3, "deleted": true }
```

| 状态码 | detail |
|---|---|
| 403 | `需要管理员权限` |
| 404 | `用户不存在` |
| 409 | `不能删除当前登录的账号`；`系统至少需要保留一个管理员`（删除唯一的管理员） |

被删用户的令牌在下一次请求时返回 `401 用户不存在`。

## 5. 联调建议流程

```sh
# 1) 登录取令牌
curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"admin"}'

# 2) 流式问一轮（记下首事件里的 conversation_id）
# 3) 拉会话列表，确认新会话已按首个问题命名
curl -s http://127.0.0.1:8000/api/conversations -H "Authorization: Bearer $TOKEN"

# 4) 改名
curl -s -X PATCH http://127.0.0.1:8000/api/conversations/$CID \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"改名验证"}'

# 5) 回放历史
curl -s http://127.0.0.1:8000/api/conversations/$CID/messages \
  -H "Authorization: Bearer $TOKEN"

# 6) 软删除会话（只打标记），再拉列表确认已不在
curl -s -X DELETE http://127.0.0.1:8000/api/conversations/$CID \
  -H "Authorization: Bearer $TOKEN"
```

Windows PowerShell 下 `curl` 是 `Invoke-WebRequest` 的别名，请显式使用 `curl.exe`；`PATCH` 在 PowerShell 5 的 `Invoke-RestMethod` 中不被支持，用 `curl.exe -X PATCH` 最省事。
