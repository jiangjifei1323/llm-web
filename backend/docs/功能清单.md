# 后端功能清单

- 服务：`llm-web` 问答助手后端（FastAPI）
- 版本：`0.1.0`
- 更新时间：2026-10-21
- 配套文档：[接口文档](接口文档.md)

## 1. 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 应用入口 | [app/main.py](../app/main.py) | 路由、请求/响应模型、会话归属校验、SSE 流式问答 |
| 认证 | [app/auth.py](../app/auth.py) | bcrypt 密码哈希、JWT 签发与校验、`get_current_user` 依赖、`require_admin`（后台接口专用，非管理员 403）、启动播种管理员 |
| 数据层 | [app/db.py](../app/db.py) | SQLAlchemy 模型、建表与轻量迁移、会话与问答的读写、用户表读写（列表、查重、改名改密、管理员计数、删除） |
| 大模型客户端 | [app/llm.py](../app/llm.py) | OpenAI 兼容接口调用（非流式 / 流式）、未配置 Key 时的 mock 回答 |
| 配置 | [.env.example](../.env.example) | 环境变量模板（实际值写入被 git 忽略的 `backend/.env`） |

## 2. 用户与认证

| 能力 | 说明 |
|---|---|
| 注册 | 用户名 2–32 位（字母、数字、下划线、连字符、中文），密码 4–64 位；重名返回 409；注册成功直接下发令牌（免二次登录） |
| 登录 | 用户名/密码校验，失败统一返回 401「用户名或密码错误」，不泄露用户名是否存在 |
| 当前用户 | 通过令牌解析出用户信息（用户名、是否管理员） |
| 密码存储 | `bcrypt` 加盐哈希，库中只存 `password_hash`，不可逆 |
| 令牌 | JWT（HS256），载荷含 `sub`/`username`/`is_admin`/`exp`；有效期 `JWT_EXPIRE_HOURS`（默认 24 小时）；**无状态**，服务端不保存会话，因此重启服务不会让已登录用户掉线 |
| 管理员种子 | 启动时若不存在 `admin` 则创建 `admin/admin`；已存在则不覆盖（便于改密） |
| 鉴权方式 | 请求头 `Authorization: Bearer <token>`；缺头/过期/无效/用户不存在分别返回对应中文提示的 401 |

## 3. 后台用户管理（仅管理员）

| 能力 | 说明 |
|---|---|
| 接口前缀 | `/api/admin/users`，四个接口全部依赖 `require_admin`，非管理员访问返回 403「需要管理员权限」 |
| 用户列表 | `GET /api/admin/users` 返回系统所有用户（id、用户名、是否管理员、创建时间），按 id 正序，**无分页**；响应不含密码哈希 |
| 新建用户 | `POST /api/admin/users` 返回 201，用户名/密码约束同注册，可一并指定 `is_admin`；重名返回 409 |
| 修改用户 | `PATCH /api/admin/users/{id}` 支持改名、重置密码、切换管理员身份；三个字段均可选，不传即保持原值（密码留空表示不改），全空补丁返回 422；目标不存在 404，重名 409 |
| 删除用户 | `DELETE /api/admin/users/{id}` 为**硬删除**，删除前在同一事务内软删除该用户未删除的会话，避免无主会话被他人认领；目标不存在 404 |
| 安全护栏 | 不能删除当前登录账号（409）；不能删除或取消最后一个管理员（409），保证系统始终有管理员可用 |
| 令牌失效 | 令牌按 `username` 反查用户，因此管理员**给自己改名**后旧令牌立即失效需重新登录；给别人改名不影响其令牌，重置他人密码也不会注销其已登录会话 |

## 4. 会话管理

| 能力 | 说明 |
|---|---|
| 会话标识 | 前端不传 `conversation_id` 时由后端生成 UUID4（36 字符字符串） |
| 会话归属 | 落库时写入 `user_id`；用户体系上线前的「无主会话」在被访问时自动认领给当前用户 |
| 越权拦截 | 访问他人会话返回 403；管理员可访问任意会话 |
| 会话列表 | 返回当前用户未软删除的会话摘要（名称、最近更新时间），按最近更新倒序；一次查会话 + 一次 `GROUP BY` 聚合，无 N+1 查询 |
| 会话名称 | 独立字段 `conversations.title`，**只在用户提出第一个问题时写入**（取该问题，去空白、截断到 200 字符）；改名后继续追问不会被覆盖；名称为空时列表回落显示「新会话」 |
| 会话改名 | `PATCH /api/conversations/{id}`，仅限本人会话；返回后端最终保存的名称（已去空白、截断） |
| 会话删除 | `DELETE /api/conversations/{id}`，仅限本人会话（管理员可删任意会话）；软删除，只把 `deleted_at` 置为删除时间，会话与消息保留在库内，对所有读接口不可见；目标不存在或已删除返回 404 |
| 历史回放 | 按时间顺序返回会话内的问答，展开为 `role/content` 序列，供前端还原对话 |

## 5. 问答能力

| 能力 | 说明 |
|---|---|
| 非流式问答 | `POST /api/chat`，一次返回完整回答、模型名、会话 id |
| 流式问答 | `POST /api/chat/stream`，SSE 逐块推送增量文本，结束推送 `[DONE]`，前端可做打字机效果 |
| 提示词 | 固定注入 system 指令：「你是一名乐于助人的问答助手，请用简体中文回答问题。」 |
| 上下文来源 | 优先用前端传的 `history`（最多 40 条）；若未传但 `conversation_id` 已存在，则从数据库自动补最近 40 条历史 |
| 落库 | 一轮问答存为一行（`question` + `answer` + `model`），流式与同步两条路径均落库 |
| 错误处理 | 非流式：上游异常抛 `RuntimeError`，未注册异常处理器，客户端收到 500（响应体 `Internal Server Error`，中文错误详情只进服务端日志）；流式：响应头已发出无法改状态码，改为下发 `{"error": "..."}` 事件 |

## 6. 大模型接入

| 能力 | 说明 |
|---|---|
| 协议 | 任意 OpenAI 兼容服务（`POST {LLM_BASE_URL}/chat/completions`），可对接 OpenAI / DeepSeek / 阿里云百炼 / 通义 / Moonshot 等 |
| 可配置项 | `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_TEMPERATURE` |
| 超时 | 非流式 60 秒，流式 120 秒 |
| 模型名回传 | 非流式取上游响应中的 `model`（缺省用配置值）；流式落库用配置的模型名 |
| mock 模式 | 未配置 `LLM_API_KEY` 时返回占位回答，模型名为 `mock`；流式模式下逐字符产出并间隔 20ms，便于前端在无密钥环境下联调 |

## 7. 数据与迁移

| 能力 | 说明 |
|---|---|
| 数据库 | PostgreSQL（`postgresql+psycopg`，SQLAlchemy 2.x 同步引擎，`pool_pre_ping` 自动剔除失效连接） |
| 表结构 | `users` / `conversations` / `messages`，详见接口文档第 2 节 |
| 建表 | 启动时 `Base.metadata.create_all`，开发阶段不引入 Alembic |
| 轻量迁移 | `create_all` 不会给已存在的表加列，故启动时按序执行 5 个幂等迁移：补 `conversations.user_id`、旧 `messages`（`role/content` 两行）重建为 `question/answer` 单行、补 `conversations.title` 并按每个会话的首个问题回填、补 `conversations.deleted_at`（存量会话取 NULL，即未删除）、把 `created_at` 统一为 `timestamp(0) without time zone` |
| 迁移顺序约束 | `title` 回填依赖 `messages.question`，必须排在 `messages` 迁移之后 |
| 时间语义 | 存无时区的北京时间墙上时间，秒级精度；列表展示由前端格式化 |
| 软删除与级联 | 接口删除会话是软删除，只置 `deleted_at`，会话行与消息都不动；`messages` 的 `ON DELETE CASCADE` 仅在直接删除库中的会话行时生效；后台删除用户是硬删除，接口会先在同一事务内把该用户未删除的会话软删除，`conversations.user_id` 的 `ON DELETE SET NULL` 是直接改库时的兜底 |

## 8. 运维与联调

| 能力 | 说明 |
|---|---|
| 健康检查 | `GET /api/health`（免鉴权），返回进程状态与数据库连通性，数据库异常时不抛错而是回显错误串 |
| 交互式文档 | FastAPI 自带 Swagger UI <http://127.0.0.1:8000/docs> 与 ReDoc `/redoc`（URL 路径，与本目录无关） |
| CORS | 开发阶段放开全部来源/方法/头；走 Vite `/api` 代理时并不依赖该配置 |
| 启动方式 | `uv sync` 后 `.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`（不带 `--reload`，改代码需手动重启） |

## 9. 已知限制与待办

| 项 | 说明 |
|---|---|
| 无登出/改密 | JWT 无状态，登出仅由前端清除本地令牌；未提供用户自助修改密码机制（管理员可在后台重置他人密码），也没有令牌吊销机制 |
| 后台用户列表无分页 | `GET /api/admin/users` 一次返回全部用户，用户量大时需改成分页 + 搜索 |
| 流式中途断开不落库 | 流式回答在迭代完成后才写库，客户端提前关闭页面会丢失这一轮问答 |
| 默认管理员口令 | `admin/admin` 为种子口令，部署前必须修改，并把 `JWT_SECRET` 换成随机长字符串 |
| 同步实现 | 数据层为同步引擎、流式生成器为同步迭代，由 Starlette 放入线程池执行；高并发场景需评估连接池与线程池上限 |
